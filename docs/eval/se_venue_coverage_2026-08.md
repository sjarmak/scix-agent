# Software-engineering venue coverage audit — 2026-08-06

## Question

Can a review aimed at the software-engineering community treat SciX plus arXiv
as adequate coverage for ICSE, FSE, ASE, ISSTA, *Empirical Software
Engineering* (EMSE), *IEEE Transactions on Software Engineering* (TSE), *ACM
Transactions on Software Engineering and Methodology* (TOSEM), and relevant
CSCW work?

No. This diagnostic rejects the assumption of adequate coverage. It is not a
recall estimate for SciX, OpenAlex, any venue, or software engineering as a
field.

## Method

The *Engineering Reliable Coding Agents* release audit ran eight preserved
topic queries over OpenAlex metadata for 2018 through 2026-08-06 and restricted
candidates to the named venues. The query set covered coding agents,
repository-scale automation, code search and retrieval, evaluation and
benchmark validity, automated review and testing, developer trust and human
factors, incident recovery, and multi-agent software work.

After DOI and title deduplication, the probe contained 148 candidate records. A
40-record DOI sample was selected by sorting the SHA-256 value of
`ERCA-SE-COVERAGE:<doi>`. Every sampled DOI was then issued as an exact DOI
query to SciX. Eight produced an exact DOI match.

The complete 148-record candidate set, preserved queries, provider-access
status, and machine-readable sample ship in the monograph companion under
`methodology/software-engineering-coverage/`. This report retains the sample
below so the SciX conclusion is reviewable without the manuscript workspace.

A follow-up known-set audit checked all 26 TSE candidates in the OpenAlex
probe, rather than only the eight selected into the deterministic sample. All
26 matched SciX by exact normalized DOI. This confirms that the 32 nonmatches
in the sample came from the other venue families; it does not estimate
topic-search recall within TSE or coverage of TSE as a whole.

TSE records matched, while none of the 32 sampled records from the other four

## Provider and licensing constraints

The audit client received HTTP 403 from ACM Digital Library search, and Scopus
returned HTTP 401 without credentials. An IEEE key is now configured, but the
provider returns HTTP 403 `Developer Inactive` while application activation
is pending. These statuses explain why the monograph's publisher-native search
remains a release gate; they do not turn OpenAlex into a publisher-native
source.

On 2026-08-06 an IEEE Xplore Metadata Search application and key were created
for the monograph supplement. A redacted DOI and query-text smoke test reached
the publisher endpoint but returned HTTP 403 with `Developer Inactive`; the
portal showed that application activation was still pending. The checked-in
plan `docs/eval/erca_ieee_xplore_search_plan_2026-08.json` expands eight review
topics across eight journal or conference-title filters (64 query cells). The
review-only client checkpoints DOI and IEEE article identifiers locally and
publishes aggregate query provenance; it does not retain IEEE-returned titles,
abstracts, author lists, or full text. No publisher-native IEEE result is
claimed until the provider activates the application and the plan completes.

After activation, run the bounded plan from the repository root:

```bash
set -a
. ./.env
set +a
.venv/bin/python scripts/run_ieee_xplore_review.py \
  --plan docs/eval/erca_ieee_xplore_search_plan_2026-08.json \
  --private-output local-research-artifacts/erca-ieee-2026-08/private-identifiers.json \
  --public-output docs/eval/erca_ieee_xplore_search_summary_2026-08.json
```

The ignored private checkpoint is resumable within the daily allowance. The
public output contains query strings, filters, fingerprints, aggregate counts,
and truncation flags but no record identities or descriptive IEEE content.

The Scopus plan
`docs/eval/erca_scopus_search_plan_2026-08.json` uses the same eight review
topics across eight journal and conference filters (64 query cells). Its
syntax follows Elsevier's documented `TITLE-ABS-KEY`, `EXACTSRCTITLE`,
`CONFNAME`, and `PUBYEAR` fields. The client sends the API key in the
`X-ELS-APIKey` header, accepts an optional institutional token, checkpoints
DOI and Scopus EID identifiers with owner-only permissions, and publishes only
aggregate provenance. It is ready to run once `ELSEVIER_API_KEY` is
configured:

```bash
python3 scripts/run_scopus_review.py \
  --plan docs/eval/erca_scopus_search_plan_2026-08.json \
  --private-output local-research-artifacts/erca-scopus-2026-08/private-identifiers.json \
  --public-output docs/eval/erca_scopus_search_summary_2026-08.json
```

If the host is outside the institutional network, Elsevier may require an
`ELSEVIER_INST_TOKEN` in addition to the API key. A credential alone does not
guarantee subscriber entitlements.

ACM Digital Library is intentionally manual. ACM's end-user policy prohibits
robots or intelligent agents and systematic downloading. The checked-in
`erca_acm_dl_manual_plan_2026-08.json` defines 48 topic-by-publication cells,
and `erca_acm_dl_manual_protocol_2026-08.md` records the allowed browser
search, citation-export, deduplication, screening, and reporting procedure. No
ACM result will be described as publisher-native until that manual run is
complete.

OpenAlex and Crossref metadata can be used for discovery and identity
resolution. They cannot establish that the corresponding publisher indexes
were searched, and they do not authorize model processing of closed full text.
SciX's existing OA/preprint gate remains binding for body processing.

## Decision

ADR-017 selects a provenance-visible federated metadata lane. SciX may use its
existing OpenAlex snapshot to discover non-ADS records and Crossref to resolve
identity, but search results must expose the source lane and must not imply
publisher-native coverage. Direct ACM, IEEE, and Scopus searches remain
separate review evidence.
