## What the convergence actually found

The predecessor handoff expected A13 to be ~19 `UndefinedTable` failures from
ADR-015/016 drift. **Three were.** The rest were latent defects the drifted test
database had been masking, and two were bugs in production code. If you take one
thing from this document: a schema-drifted test database does not just fail, it
*hides* failures, and the hidden ones were worse than the visible ones.

1. **The P0 was wider than filed.** `tests/helpers.py` had the same
   `SCIX_DSN`-first bug, and `helpers.DSN` is what `test_uat.py` (26 write
   statements), `test_harvest_ads_data.py` and `test_dictionary.py` gate on via
   `is_production_dsn(DSN)`. So exporting the documented guard made those
   destructive suites **silently skip** while other modules still reached
   production — both failure directions from one line.
   `tests/test_dsn_guard.py` now fails on the pattern (written RED first, proven
   against a probe module).
2. **`src/scix/eval/real_data.py` queried the dropped `paper_embeddings`**, so
   `scripts/eval_three_way.py` seed sampling had been broken since ADR-015.
   Repointed at `indus_qdrant_synced`, verified on prod (5 seeds, 431.9 s).
3. **Every `pytest tests/` fired a ~7-minute scan at production.** That test's
   gate read `SCIX_DSN or os.path.exists("/var/run/postgresql")` while its header
   claimed "opt-in" — true on any host with a local Postgres socket. Now
   `SCIX_EVAL_REAL_DB=1`.
4. **Migration-replay tests mutated the shared `scix_test`.** Replaying `001`
   re-created `paper_embeddings`, so whether it existed depended on test order.
   Four modules now build throwaway databases via `tests.helpers.throwaway_db`.
5. **`scripts/demo_readiness_smoke.py` set `QDRANT_URL` at import time**, pointing
   the whole pytest session at a dead port.
6. **`papers_fulltext.sections_tsv` exists in production in a shape no migration
   describes** — migration 061 says `GENERATED ALWAYS`, prod says plain column,
   because the ADR-016 Phase 1b swap rebuilt the table without the expression.
   `scix_test` was matched to **production**, not to the migration.

## Also shipped after the goal closed

**ws5 — the nightly scan is bounded.** The unembedded anti-join was a seq scan
over every paper hashed against the full 35M-row watermark: ~10.1M planned, 530 s
before the first row cold, 98% of a 540 s drain whose GPU work was ~10 s.

The predecessor's proposal (bound by ingest recency) needed a new index —
`papers.entry_date` is unindexed `text` and `papers` has no ingest timestamp.
`idx_papers_year` already exists, so bounding on publication year drops the plan
to ~2.06M with **no new DDL**. Verified on the SQL the code generates, not a
hand-typed approximation.

The trade-off is why `--full` exists: the bound is on **publication** year, not
ingest date, so a newly ingested 1995 paper is invisible nightly. Backfills
(bead `1239`, annotated) must pass `--full`.

**p0h — the health gate has a working alert sink.** It ran only from the last
line of `daily_sync.sh`, so the failure it exists to catch stopped it running.

be implemented as written.** There is no MTA: no `sendmail`, no `mail`, no
`mailx`, no `msmtp`; postfix, exim4 and msmtpd inactive. That line would deliver
nothing, silently, while looking like monitoring — the same silent-failure class
the gate exists to remove, installed as its fix.

`--notify` maintains exactly one bead labelled `pipeline-health`: breach opens or

## Traps that will cost you an hour

Ordered by how likely you are to hit them.

- **The suite needs `scix-batch`.** In the default shell cgroup it was
  **OOM-killed at 17 minutes**; under `--mem-high 40G --mem-max 60G` it finishes
  in ~2. The 17-minute crawl was swap thrash, not slow tests. This is not in any
  earlier handoff and it looks like a hang.
- **Test a cron line the way cron runs it.** The first install of the p0h entry
  omitted the `cd`, and cron runs from `$HOME`, so it would have failed every
  morning. It passed a dry-run only because that ran from inside the repo. Use
  `cd /home/ds && env -i HOME=/home/ds /bin/sh -c "<the line>"`.
- **`bd` is in `~/.local/bin`, which is not on cron's default PATH.** Set PATH
  inline on the entry rather than relying on the crontab's `PATH=` line position.
- **The beads store has a brief write-visibility lag.** `bd list --label`
  immediately after `bd create` in the same shell can return 0 rows and reads
  correctly seconds later. Harmless at a 24h cadence, alarming when testing
  back-to-back — it looks like the label filter is broken.
- **`bd update -d` REPLACES the description.** It clobbered bead `1239` during
  this session. Recovered from Dolt history
  (`dolt ... sql -q "select description from issues as of '<commit>'"`), but read
  the current description first and append to it.
- **`QDRANT_URL` is not in your shell.** `daily_sync.sh` sources `.env`; a manual
  run does not, and `scix-batch` does not either. `set -a; source .env; set +a`
  before `scripts/embed.py`. Smoke-test with `--limit 100`.
- **Cron is `15 6 * * *` local = 10:15 UTC.** Log stamps are UTC; the host is
  UTC-4.
- **The pre-push hook is real** — gitleaks against `.gitleaks.toml`. Don't reach
  for `--no-verify`.
